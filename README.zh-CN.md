# 校园电动汽车充电分析

[在线系统](https://s1-pop-assessment2-jsdhilgeqw6duwytp6qvaf.streamlit.app/) · [English](README.md)

本系统是 Taylor's **编程原理 Assessment 2** 小组项目，使用老师提供的 1,200 条充电记录，帮助校园设施管理人员分析充电规律、比较高峰与非高峰使用情况，并预测一次充电的运行状态。

项目在 Assessment 1 充电计费系统的基础上，完成数据处理、模型比较、中英文网页开发和云端部署。预测使用手动输入的充电参数，目前没有连接真实充电桩或传感器。

## 系统功能

| 模块 | 主要功能 |
| --- | --- |
| **数据概览** | 总充电量、平均充电时长、估算高峰收入、可选碳减排量、筛选后的记录表和 CSV 下载。 |
| **图表分析** | 充电量与电池温度散点图、AC/DC 充电次数分布、高峰与非高峰平均充电量。三张图均随筛选条件更新。 |
| **状态预测** | 通过侧栏表单预测正常、电网负荷突增或过热，以不同颜色显示结果，同时展示计算功率和高峰标记。 |

数据概览和图表支持按充电桩类型、用户类型、时段和最低充电量筛选。右上角可以切换中英文；下载的 CSV 保留原始字段名和类别代码。

可选设置包括净碳减排系数和温度提醒阈值，默认不假设具体数值。以 `[TASK3]` 开头的操作日志会在本地控制台或云端日志中记录页面切换、筛选、图表生成、下载请求及已提交的预测。

## 开发过程

### 1. 数据检查与处理

老师提供的数据包含 AC/DC 充电桩、教职工/学生/访客用户、充电测量值及状态标签。实际温度字段为 `Battery_Temp_C`，本项目按该电池温度字段进行分析。

Pandas/NumPy 数据处理脚本检查缺失值和重复记录编号，用各列中位数填补数值缺失，验证测量值，并计算：

- 平均充电功率：`Power_kW = Energy_kWh / (Duration_Mins / 60)`。
- 高峰标记 `Peak_Hour_Flag`：根据开始时间与持续时长，判断充电过程是否与 **12:00–17:00** 重叠。

首次清洗时，**25 个时长缺失值**填为 **97 分钟**，**35 个电量缺失值**填为 **13.28 kWh**。没有发现重复充电记录，因此保留全部 1,200 条数据。脚本还按充电桩类型、高峰标记及两者组合，输出平均电量和平均电池温度。

仓库中的 `0_ev_campus_dataset.csv` 是**已处理的工作数据**，共有 11 列。`0_` 只是数据文件的编号，不表示未经修改的原始副本。Task 1 会更新同一份 CSV。当前保留已有的 AC/DC 充电桩分组，没有单独实现能效类别划分。

### 2. 训练与比较两个模型

训练脚本使用九项输入预测 `Grid_Status_Label`：充电桩类型、用户类型、开始时间、时长、电量、超时停车、电池温度、功率和高峰标记。记录编号及目标标签不作为模型输入。

数据按类别比例划分为 **80% 训练集和 20% 测试集**，即 **960 条训练记录、240 条测试记录**，固定 `random_state=42`。充电桩及用户类型进行独热编码，测试集字段与训练集对齐。决策树与包含 100 棵树的随机森林在同一测试集上比较。

| 模型 | 准确率 | 宏平均精确率 | 宏平均召回率 | 宏平均 F1 |
| --- | --- | --- | --- | --- |
| **随机森林** | **85.00%** | **0.7815** | **0.7584** | **0.7674** |
| 决策树 | 83.75% | 0.7577 | 0.7369 | 0.7444 |

宏平均指标对各状态给予相同权重。脚本优先比较宏平均 F1，相同时再比较准确率。最终选出**随机森林**，连同输入字段、编码信息一起保存。决策树只在内存中训练和评估，没有导出文件。保存的模型保留测试时使用的训练结果，没有再使用测试集重新训练。

![两个模型在测试集上的混淆矩阵](task2_confusion_matrices.png)

类别分布为：正常 898 条、电网负荷突增 172 条、过热 130 条，存在类别不均衡。目前对电网负荷突增的识别较弱。这些得分仅反映当前数据与划分，不能保证新场景下的准确性。Task 1 在划分训练集前计算了全体数据的中位数，因此当前评估没有完全隔离预处理过程。

### 3. 开发和完善网页

Streamlit 网页将处理后的数据、保存的模型接入侧栏导航的三个页面。数据和模型加载使用缓存，提交预测时直接调用已有模型，不在页面操作时重复训练。

随后增加中英文切换、筛选结果下载、可选分析设置和操作日志。图表改用 **Agg** 后端，解决 macOS 下工作线程无法创建桌面绘图窗口的问题；同时按可用字体显示中文图表。程序既支持 Streamlit 终端命令，也支持 PyCharm 普通 **Run** 操作。

本地检查覆盖了中英文页面、三张图表、筛选与空结果、下载回调、模型加载和提交预测。这些检查不能替代完整的线上功能验证。

### 4. 上传 GitHub 并部署到云端

项目已上传至小组的 [GitHub 仓库](https://github.com/taylors-0395483/s1-pop-assessment2)。Python 依赖固定为与模型环境一致的版本，并通过 `packages.txt` 为 Linux 云端安装**文泉驿正黑**中文字体。

部署平台为 **Streamlit Community Cloud**，使用 `main` 分支、`task3_app.py` 入口和 Python **3.12**。由于仓库属于 GitHub 组织，部署前还单独批准了 Streamlit 的组织 OAuth 访问权限。完成授权后，系统部署到本文顶部的在线地址。

云端直接读取仓库已有的 CSV 和模型，启动时不运行清洗或训练脚本。后续推送到部署分支的程序及依赖更新会由 Community Cloud 获取；README 更新只改变项目说明，不改变分析或预测逻辑。

## 本地运行

在项目目录下，使用 Python 3.12 执行：

```bash
python -m pip install -r requirements.txt
python -m streamlit run task3_app.py
```

打开终端输出的网址，按 `Ctrl+C` 停止。使用 PyCharm 时，选择已安装依赖的环境，将 `task3_app.py` 作为普通 Python 脚本运行。

仓库已包含处理后的数据和模型。需要重新生成时，按顺序执行：

```bash
python task1_data_pipeline.py
python task2_train_model.py
```

Task 1 覆盖工作 CSV，Task 2 覆盖其三个产物文件。替换数据或模型后，请重启网页以刷新缓存。

## 结果解释与当前进度

高峰收入是**估算值**，采用 Assessment 1 的阶梯时薪、时长向上取整、费用上限、教职工/学生折扣、高峰附加费和超时停车附加费，统计与高峰重叠的记录的整次估算费用。数据缺少首次免费、Eco-Pass 和补卡字段，因此不计算这些费用变化。碳减排量取决于用户输入的系数；指标变化值比较筛选数据与全体数据，不是与上一日期比较。

核心数据处理、模型比较、网页、GitHub 上传及首次云端部署已经完成。完整的线上功能检查、五分钟演示视频和作业声明/AI 使用附录仍属于后续提交工作。开发、文档及排错过程使用了 AI 辅助；本 README 不能替代要求提交的声明和聊天记录附录。
